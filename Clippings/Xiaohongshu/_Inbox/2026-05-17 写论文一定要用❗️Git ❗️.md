# 写论文一定要用❗️Git ❗️

> **@爱练腿的龙脖（AI版）** · [原文](https://www.xiaohongshu.com/discovery/item/69e9e4ea000000001f030c04?source=webshare&xhsshare=pc_web&xsec_token=CBJjmc4H7VLoI_714eXqLgTLt8SNAjttzc05Jxji-gBd4=&xsec_source=pc_share)

## 要点

- **进度可追溯**：正文、表格、脚本每次修改都有提交记录，论文与代码共用一条时间线。
- **远端备份**：推送到远程降低误删、换机风险；本地默认分支 `main`，追踪范围由各项目 `.gitignore` 决定。
- **Agent 协作**：用分支 / worktree 把主线写作与 agent 试错拆开，合并前可 diff（适配 Cursor/Codex 改稿）。
- **协作共享**：合作者共享仓库与版本史，减少「终稿修订版 v9」式传文件。
- **推荐目录**：`Data / Program / Results / Manuscripts / Tasks / Submissions / Reference`。
- **应忽略**：原始数据、投稿包、临时文件、Stata 日志、LaTeX 中间产物；保留正文、脚本、表格接口等需版本化的内容。
- **VS Code 插件**：Git Graph、Git History、StataRun、LaTeX Workshop、Markdown All in One（作者常用组合）。
- **定位**：Git 让论文项目可复盘、可并行；适合与当前 vault 的 Cursor + Obsidian 科研流并用，非替代 Zotero。

## 正文

我最近很喜欢打开论文仓库的版本树。🌿这一周改了哪段正文、agent 新开了哪条试验分支、哪次稳健性检验留在独立工作树里，一眼就能看到。论文项目开始像一个能追踪、能回退、能并行推进的系统。🧭这也是我越来越想把 Git 推荐给文科同学的原因📝
1️⃣Git最直接的价值，就是【进度可追溯】。正文改过什么、表格换过哪版、脚本什么时候动过，都能在提交记录里留下坐标。论文、代码、结果终于能对在一条时间线上。📍
2️⃣其次是【线上备份】。☁️ 仓库推到远端之后，电脑临时出问题、文件夹误操作、跨设备切换，心里会稳很多。我现在本地默认分支就是 `main`，真正决定项目秩序的，是每个研究项目自己的 `.gitignore`🔒
3️⃣是【agent 协作】。🤖 让 Codex 改脚本、修表格、补正文时，我很在意它这次到底动了哪里。开分支、派生工作树之后，主线写作和实验试错可以拆开推进，合并前也更容易检查差异。🧪
4️⃣是【共享协作】。👥 和同学、导师、合作者共享仓库时，大家看到的是同一套目录和同一串版本记录，沟通成本会低很多。比起反复传“终稿修订版”，这种方式会清楚很多。🔗
	
如果是标准化论文项目，我现在习惯用 `Data / Program / Results / Manuscripts / Tasks / Submissions / Reference` 这套结构。📂
`.gitignore` 里优先忽略数据、投稿包、临时文件、Stata 日志、LaTeX 中间产物，把真正需要追踪的正文、脚本、表格接口留下来。
	
VS Code 里我常用的也很固定：【Git Graph】、【Git History】、【StataRun】、【LaTeX Workshop】、【Markdown All in One】🛠️。
Git 已经很适合论文项目，它让研究过程真正可复盘。
	
🌱 对文科论文来说，项目一旦进入 Git，整套工作流会更稳，也更适合和 agent 一起往前推。✅
