## 何时走本流程

- 主线叙事里已是「前期基础 / 投稿中 / Done」  
- 旧工作流目录里堆满 Word/PDF/探索性出图，但日常只需**终稿 + 少量改格式**  
- 需要稳定路径给 Obsidian / Cursor，又**不必**把 `Figuers/`、`csv/` 整包迁入 vault  
- （可选）印象笔记笔记本组需**整包迁入**某前期项目，保留正文、图片与笔记本内互链  

## 入库步骤（约 30–45 min / 篇）

### Step 0 · 定名与科学定位（5 min）

正式名**必须**能在 [[00 工作系统3.0：海马+抑郁症+认知损伤的机制及诊疗]] 里一眼定位，建议：

| 部分 | 规则 | 范例（本篇） |
|------|------|----------------|
| 前缀 | 工作系统 slot：`1a` `2a` `1a-2a` 等 | `1a-2a` |
| 主题 | 科学问题 + 手段/对象（中文短句） | `海马宏观微观分割与抗抑郁疗效预测` |
| 文件夹 | `前期产出/<前缀> <主题>/` | `1a-2a 海马宏观微观分割与抗抑郁疗效预测/` |
| 总控笔记 | 与文件夹同名 `.md` | 同左 |
| nickname | 可选；仅 `frontmatter`，不出现在文件夹名 | — |
| 运营 3.x | 标题用**正式项目名** | `3.1 · 1a-2a 海马宏观微观分割与抗抑郁疗效预测` |

- [ ] 按上表确定正式名（**不用**「Paper 投稿」作文件夹名——那是状态，不是科学定位）  
- [ ] 建文件夹 + 总控笔记（frontmatter：`science_slots`、`project_line`、`science_map`、`status`、`manuscript_title_en`）  
- [ ] 在工作系统 3.0 **对应 1a/2a/… 条目**双向链到总控笔记  
- [ ] 若有旧昵称：另建 `前期产出/<旧名>.md` 别名页链到新笔记（可选）  

### Step 1 · 清点源目录（10 min）

通常两类路径（可并存）：

| 类型 | 示例 | 用途 |
|------|------|------|
| **当前投稿包** | `...\Radiology-Adv 最新` | 最新主稿、cover、response、title page |
| **较全材料包** | `...\Radiology投稿版本 较全` | Figure.pdf、Supplementary、Tables |

在 `定稿/README` 填写**源路径**（不迁移整棵树）。

### Step 2 · 复制定稿进 vault（10 min）

只复制**当前投稿用**终稿（约 8–12 个文件，~3–15 MB），建议命名：

| 库内名 | 内容 |
|--------|------|
| `manuscript_*.docx` | 可编辑主稿（确认哪一版为最新 clean-plain） |
| `manuscript_*.pdf` | 投稿 PDF |
| `figures_main.pdf` | 主文图 |
| `supplementary.pdf` | 补充材料 |
| `tables.docx` | 主文表 |
| `cover_letter.docx` / `response_*.pdf` / `title_page.docx` | 按需 |

**勿复制**：多版 Word、`Figuers/` 探索图、`csv/` 中间表、`.psd`、旧杂志整套投稿包。

### Step 3 · 生成 AI 用 digest（2 min）

```powershell
cd "<vault>\0 工作流\scripts"
.\Update-ManuscriptDigest.ps1
```

产出：

| 文件 | 用途 |
|------|------|
| `manuscript_digest.md` | **瘦身版**（~14 KB：Title·Abstract·Intro/Results/Discussion 摘录·Conclusions 全文）→ 日常 @ |
| `manuscript_digest_full.md` | Pandoc 全文备份（~80 KB），逐句核对时用 |

改 Word 后 **rerun 脚本**即可同步。

### Step 4 · 挂接运营线（5 min）

- [ ] [[同期项目-下一节点]] 增加 `3.x` 下一节点（每线 1 条）  
- [ ] [[本周科研推进]]「支线」按需加 follow-up  
- [ ] [[00 小章鱼的 All in One]] `3.x` 链到总控笔记（进度不写死在 All in One）  

### Step 5 · 发表后（一次性）

- [ ] Zotero 建条目 + PDF  
- [ ] Obsidian Literature Note（[[3.1 Workflow ：Zotero+Obsidian 文献由进到出全流程]]）  
- [ ] 总控笔记 `status: 已发表`，下一节点从 3.x 移除或归档  

### Step 6 · 印象笔记 HTML 迁入（可选 · 过渡）

> **终态**：印象笔记 **不**保留为长期文献池；迁移完成后删除 `7 可复用知识库/印象笔记存档/`。可晋升内容 → Zotero（S0）+ `7 可复用知识库/literature/`（S1），见 [[0 工作流/workflows/3.8 Workflow ：文献库组织架构]]。  
> **定稿试点**：[[3c 海马实时fMRI神经反馈与情绪改善]]（2026-05-23，67 篇 HTML）  
> 脚本说明：[[0 工作流/scripts/README-evernote-html]]

**何时用**

- 印象笔记（印象笔记 / Yinxiang）笔记本组需**整包迁入** Obsidian 某项目目录  
- 需要保留笔记正文、图片、笔记本内互链，并替代或补充该项目的 `00_ResearchTrack` / MOC  
- **不要用**加密 `.notes` 导出（需账号解密）；改用客户端 **「导出为多个网页文件 (.html)」**

**导出（印象笔记客户端）**

1. 选中目标**笔记本组**（如 RTNF）→ 导出  
2. 格式：**多个 HTML**（非单页 HTML / MHT / `.notes`）  
3. 输出到固定目录，例如 `F:\SYSTEM\DESKTOP\<项目名>-印象笔记导出`  
4. 确认同目录下有 `*.html` 与对应 `*_files/` 附件夹  

**库内落点（3c 范例）**

| 路径 | 内容 |
|------|------|
| `1 主线项目/前期产出/<项目>/印象笔记归档/notes/` | 按主题分类的 `.md`（正文未人工改写） |
| `…/印象笔记归档/attachments/` | 各笔记 `*_files` 资源 |
| `…/印象笔记归档/RTNF_MOC.md` | 由原 `*index*.html` 整理的目录 + 分类索引 |
| `…/00_ResearchTrack.md` | 项目运营 track（Dashboard 抓取文件名） |

3c 分类前缀：`01_SMA` · `02_海马fMRI分析` · `03_行为与统计` · `04_实验与工作笔记` · `05_文献阅读` · `06_方案与基建` · `07_其他`

**导入命令**

```powershell
cd "e:\Obisidian\MyObisidian\0 工作流\scripts"
python import_rtnf_evernote_html.py --export-dir "F:\SYSTEM\DESKTOP\RTNF-印象笔记导出"
```

- `--dry-run`：仅统计，不写库  
- 修改 `import_rtnf_evernote_html.py` 顶部 `PROJECT` / `ARCHIVE` 可复用到其他前期项目（或复制脚本改项目名）

**脚本行为（不改正文语义）**

1. HTML → Markdown（html2text）  
2. 图片改为 Obsidian 嵌入：`![[1 主线项目/…/印象笔记归档/attachments/…]]`（避免 `../attachments/` 在 Obsidian 中失效）  
3. 笔记本内 `.html` 互链 → vault 内 `[[印象笔记归档/notes/…]]`  
4. `evernote:///` 内链保留原样（未导出的笔记无法恢复）  
5. 生成 `RTNF_MOC.md`、`00_ResearchTrack.md`、归档 `README.md`

**入库后人工步骤（建议）**

- [ ] 总控笔记链到 `印象笔记归档/RTNF_MOC` 与 `00_ResearchTrack`（3c 已完成）  
- [ ] `05_文献阅读/` 有 DOI 的条目迁入 Zotero（见 [[3.1 Workflow ：Zotero+Obsidian 文献由进到出全流程]]）  
- [ ] 桌面 HTML 导出包确认 Obsidian 显示正常后可删除或移出 `DESKTOP` 作备份  
- [ ] 统计表 / `.sav` / 坚果云大文件**仍放源路径**，仅在 track 记索引（同 Step 1–2）

**已知限制**

| 现象 | 处理 |
|------|------|
| 图片路径 `].png` | Evernote/html2text 坏名；对照桌面 `*_files` 改文件名或重导 HTML |
| 加密 `.notes` | 改 HTML 导出，勿强行解密 |
| 重复导入 | 脚本会先删除整个 `印象笔记归档/` 再写入；重跑前确认无未备份的库内手写修改 |

**分线策略（混合控制台导出 · 2026-05-23）**

| 落点 | 何时 | Cursor 索引 |
|------|------|-------------|
| `1 主线项目/前期产出/<项目>/印象笔记归档/` | 已确认归属某项目（白名单或整包，如 3c / 1a-2a 核心 4 篇） | 默认索引 |
| `7 可复用知识库/印象笔记存档/` | 混合笔记本组**先全量导出、迁入**；周记/模板/账单等桌面删除后再入库 | **不索引**（vault 根 `.cursorignore`） |

**推荐流程**

1. 客户端导出「多个 HTML」→ 桌面固定目录  
2. 桌面删除确定不要项（周记、模板、账单、旧版工作系统等）；`cleanup_evernote_export_desktop.py`  
3. **白名单**迁入对应项目（如 `import_1a2a_evernote_html.py`）  
4. **剩余**一次性迁入垃圾场：`import_evernote_kb_archive.py` → 清空桌面导出目录  
5. 检索：在 **Obsidian** 内按 topic 搜（`Ctrl+Shift+F`，可加 `path:"印象笔记存档"`）；Cursor 需读时 **手动 `@` 单篇**，或临时注释 `.cursorignore` 后重建索引

## AI 与索引约定

- **不**为定稿单独建 `.cursorignore`（除非 vault 极大后再评估）  
- `7 可复用知识库/印象笔记存档/` **整目录**已在 vault 根 `.cursorignore`（先全量迁入、不自动索引；见 Step 6 分线策略）  
- 对话优先 `@manuscript_digest.md`，避免 @ 整份 docx/pdf  
- 正式**他人文献**仍只进 Zotero，不进 `前期产出/`
