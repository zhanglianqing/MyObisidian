# 3.9 Codex 对话 history 写入日记

> 归属：[[3.0 Workflow ：AI 原生科研工作流架构]]。  
> **痛点**：一天里 Codex / Cursor / Obsidian Copilot 等工具对话分散，重要决策容易留在聊天里，第二天难以承接。  
> **定稿调用**：用户说“看今天的对话 history，提取主要内容写到今日日记”时，按本页执行。

## 定稿摘要（调用入口）

### 触发口令

```text
帮我看一下今天的对话 history，提取主要内容然后写到今日日记里面
```

也可简写为：

```text
整理今天对话 history 写入今日日记
```

### 写入位置

统一写入：

```text
0 工作流/日程/Daily/YYYY-MM-DD.md
```

若当天 Daily 不存在，可按 `daily-optional` frontmatter 新建；若已存在，在合适位置追加：

```markdown
## 今日对话 history 小结
```

## 执行流程

1. 先读取当天 Daily，确认已有结构和已记录内容。
2. 读取 Codex 最近线程摘要，优先筛选当天创建或当天更新、且 cwd 指向本 vault 的线程。
3. 对每条线程只提取主线：已完成动作、形成的判断、明确的后续边界、需要分流的内容。
4. 不把聊天里的每句话写成流水账；合并同类项，写成 3-6 条日记式小结。
5. 写入 Daily 后，再快速复核页面，处理前后矛盾。例如早些时候写“未清理”，后续已确认清理，则应更新为最新状态。

## 来源标注规则

- **Codex 线程可读内容**：可写为“今天对话中确认 / 判断 / 形成方案”。
- **Daily 里原本已有内容**：只能写为“Daily 已有记录”，不要误说成“从 Cursor history 读取到”。
- **Cursor / Copilot / 其他工具内容**：只有当用户贴出、文件中已记录、或本地可读 history 明确可查时，才可归入对应来源。
- 若来源不确定，写成“今天记录中出现”或“现有 Daily 已记录”，避免硬归因。

## 边界

- 本流程只写 Daily，不自动改 [[本周工作台]]、[[同期项目-下一节点]]、[[本周科研推进]] 或项目页。
- 不自动迁移、归档、删除文件；若 history 小结暴露出需要迁移/归档/删除，先写“可能需要分流”，等待用户确认。
- 不读取 `0 工作流/_email_drop/` 单封邮件，除非当天对话整理明确需要复核邮件原文，且用户已授权邮件整理。
- 不把未验证的聊天印象写成事实；需要区分“已完成”“已形成方案”“未执行”。

## 推荐输出格式

```markdown
## 今日对话 history 小结

- **主题 1**：一句话说明今天围绕什么做了什么，结果是什么。
- **主题 2**：形成的判断或后续规则。
- **主题 3**：未执行但需要保留的边界或分流方向。
```
