### §一 表格列（定稿）

| 列 | 谁填 | 约定 |
|----|------|------|
| **日期** | 脚本 | `周X MM-DD`，**周一～周日**；`week_of` = 当周一 |
| **不可用时段** | 脚本 + 你 | ICS：**7T** / 早班 / 下午班 / 晚班 / 夜班 / 补休 / 休；多段 ` + `；**手填**会议、幼儿园、飞机等固定占用 |
| **预计可用** | 脚本 | **只写空档**，不写「不可用」 |
| **带娃 / 火山** | 脚本默认 + 可改 | 默认 `20–21 带读`；有**晚班** → `—` |
| **科研空档** | 你 | 按优先顺序填项目简称或 `[[链接]]`；**考虑单项耗时**，排不下则顺延至下周科研推进页 |

### 预计可用 · 速查（只写左列）

| 不可用（ICS）情况 | 预计可用时段 |
|----------|----------------|
| 休 | 全天可规划（科研） |
| 仅下午班 | 上午 + 晚上可规划（科研） |
| 仅夜班（如 22:30 后） | 白天 + 晚上可规划（科研） |
| 7T + 晚班 | 09:00–17:00 7T 可科研 |
| 仅 7T | 09:00–17:00 7T 可科研；早晚可规划（科研） |
| 补休 | 15:00–20:00 可轻量 |

**科研强度**：**7T 时段**可深度科研；其余空档非 7T 日多为规划 / follow-up；补休下午仅轻量。

### 大改版前版本留底

适用：定稿框架、主稿、摘要、投稿包等将被**新版本完全替代**的材料。

1. **当前工作版只有一份**：活跃目录中保留当前要改的主文件；新版本可以直接覆盖旧定稿框架，不在 vault 活跃区复制 `v1/v2/旧版/新版` 多份并行稿。
2. **Git 做细颗粒留底**：开工前先做一次 checkpoint（如 `before RTNF rewrite 2026-06-04`）；改完后再提交一次。需要回看旧版时走 Git history / diff。
3. **硬盘做原始留底**：旧 Word、过程稿、finalManu 等原始多版本材料保留在本地硬盘或坚果云原工作流目录；不整包同步进 vault。
4. **vault 只放可调用材料**：项目页、改稿记录、摘要草稿只引用当前工作版；如必须保留人工可读快照，放入明确归档区并写 `status: archived`、`current: false`，默认不作为下一步依据。
5. **给 AI / agent 的判断**：未被用户点名时，`_archive/`、`versions/`、`ARCHIVE-*`、硬盘旧目录都只作历史证据；当前推进以活跃工作文件和 [[同期项目-下一节点]] 为准。

## 排班接入（Full Calendar）

**插件**：社区 **Full Calendar**（`obsidian-full-calendar`）。侧边栏周视图看班次；**勿**用 iCloud/CalDAV 登录（易 401）。

**已验证设置（2026-05-20）**：

1. **iPhone 日历** → 底部「日历」→ iCloud 下排班那本 → **ⓘ** → 开「公共日历」→ 拷贝共享链接（`webcal://…`）。
2. **Obsidian** → Full Calendar → Add calendar → **ICS** → 名称如 `医院排班` → URL 把 `webcal://` 改为 **`https://`** → 保存 → `Full Calendar: Revalidate remote calendars`。

订阅 URL 勿写入公开笔记；社区版 **Calendar** 插件可卸载（与排班无关），**Daily notes** 核心插件保留。

## 每周仪式（周日或周一，约 15 min）

**节奏**：先**小结上周、更新进展**，再**排序、填时段**；Full Calendar 只作对照，不必在工作台复写整周班表。

1. **回顾上周**（约 5 min）：扫 [[本周科研推进]] 勾选情况、[[火山英语启蒙-执行日志]]、相关 Daily（若有）、各项目 track 笔记——提炼「各线实际推进了什么」。
2. **[[同期项目-下一节点]]**：上周已完成的节点勾选掉，按 [[00 小章鱼的 All in One]] 编号为每条在跑（或暂停但需记住）的线写**新的**下一节点（标题下仍只留 **1 条** `- [ ]`）；[[本周工作台]] §二 自动展示。
3. **排序**：根据 §二 更新后的进度 + **近期紧迫度**（deadline、催办、基建阻塞），列出本周 **Top 3～5** 要占时段的项（可在 §一 表头上方写一行排序备忘）。
4. 运行 `weekly_workbench_from_ics.py` 刷新 **不可用时段 + 预计可用**（或 Full Calendar 分屏手填）→ **§一** 把排序后的项填入 **带娃** / **科研** 列；排不下则写入下周 `YYYY-MM-DD 科研推进.md`。
5. **[[本周科研推进]]**：只为 §一 里占科研空档的线写可勾选任务；每条空档至少链一条。
6. **周末**（可选）：工作台底部「上次离开时的上下文」2～3 行，方便下周一接着 §二 小结。

## 科研日（不必每天写日记）

- 科研空档日 → 先看工作台 **§一** 当天填的是哪条线 → [[本周科研推进]] 或对应 Research Track。
- 要记流水 → 命令「打开/创建今天的日记」（`0 工作流/日程/Daily`，可选）。
- 火山 → 工作台 §一「带娃」列；事实 → [[火山英语启蒙-执行日志]]。
