# 3.8 文献库组织架构

> **定稿**：2026-05-29  
> **归属**：[[3.0 Workflow ：AI 原生科研工作流架构]] · 操作细节见 [[3.1 Workflow ：Zotero+Obsidian 文献由进到出全流程]]  
> **Obsidian 落地**：[[7 可复用知识库/literature/README]]  
> **范围**：文献存放、标签、内化笔记、专题外置 AI；**不含**具体会议 talk / 单篇幻灯内容。

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| **单一权威** | PDF 与元数据只在 **Zotero + 坚果云链接附件**；vault 内不长期堆 PDF 副本。 |
| **物理扁平** | Zotero Collection 仅表「阅读阶段」；科学域 / 项目归属用 **Tag**。 |
| **逻辑分面** | 多归属（全线基石 + 某 slot + 某项目）用 tag / 链接表达，**不**把同一篇拖进多个 Collection。 |
| **内化与原文分离** | 日常写作用 **Literature Note（S1）** + `[@citekey]`；PDF 仅在需要时打开或复制到专题包。 |
| **AI 工具分工** | 默认 **Cursor + Copilot + Zotero LLM**；Gemini / NotebookLM 用 **临时专题包**，不维持全库文件夹镜像。 |
| **印象笔记** | 仅作迁移过渡；迁移验收后 **删除** `7 可复用知识库/印象笔记存档/`，不纳入终态架构。 |

| 层 | 内容 | 路径 / 工具 |
|----|------|-------------|
| **S0** | PDF、元数据、citekey | Zotero；PDF：`…/zotero/literature/{Cornerstone\|My Papers\|Everything}/`；bib：`Zotero-lib/My Library.bib` |
| **S1** | 读后合成（短笔记） | `7 可复用知识库/literature/{citekey}.md`（**平面**，无子目录分类） |

| **项目** | 写稿、track、会议 | `1 主线项目/…`：**禁止**长期 `literature/` 子树；用 `[@citekey]`、`[[citekey]]`、可选 `文献-阅读队列.md` |
| **临时** | 外置 AI 专题包 | `0 工作流/工具箱/ai专题/<topic>-<YYYYMMDD>/`（用毕删除或冷归档） |

## 3. Zotero：Collection 扁平 + Tag 分面

### 3.1 Collection（三夹 · 按文献角色，每篇只属于一个）

> 拼写：**Cornerstone**（基石，非 conorstone）；**My Papers**（自有论文）；**Everything**（其余默认库）。

| Collection | 用途 | Attanger 子目录 |
|------------|------|-----------------|
| `Cornerstone` | 全线反复引用的基石文献（常配合 `scope/core` tag） | `literature/Cornerstone/` |
| `My Papers` | 本人（含共同作者）已发表 / 投稿中论文 | `literature/My Papers/` |
| `Everything` | **默认**：新入库的外文文献、备查、尚未晋升为基石者 | `literature/Everything/` |

**归入习惯**

- 新抓文献（DOI 添加）→ 先进 **`Everything`**，打 `dom/*`、`slot/*` 等 tag。  
- 确认为基石、已写 S1 / 进 MOC → 移入 **`Cornerstone`**（一篇只在一个 Collection）。  
- 自己的文章 → **`My Papers`**（可与 `scope/core` 并存，但 Collection 仍只能选一个）。

- **禁止**按项目或科学树建 Collection（如 `01_Memory_TMS`、`1a-2a`）——避免一篇多处、PDF 路径冲突。  
- **阅读进度**（未读 / 在读 / 已读）用 tag `status/*` 表达，**不**再占用 Collection 名。  
- Attanger 子目录保持 `{{collection}}`（见 [[3.1 Workflow ：Zotero+Obsidian 文献由进到出全流程]] §1.2）。

### 3.2 Tag 命名（取代原「主线项目 Collection」）

使用 **带前缀** 的彩色 tag，一篇可多选：

| 前缀 | 含义 | 示例 |
|------|------|------|
| `dom/` | 科学域（跨项目） | `dom/hippocampus`, `dom/MDD`, `dom/TMS`, `dom/rt-fMRI` |
| `slot/` | [[00 工作系统3.0：海马+抑郁症+认知损伤的机制及诊疗]] 槽位 | `slot/1a`, `slot/2a`, `slot/1a-2a`, `slot/3c` |
| `proj/` | 细到具体任务（可选） | `proj/计划1-PPC`, `proj/省面上-2025` |
| `scope/` | 重要性 | `scope/core`, `scope/supporting` |
| `status/` | 阅读流 | `status/to-read`, `status/skim`, `status/digested` |

**规则**

- **全线基石**：`scope/core` + 相关 `dom/*`，不必加 `proj/*`。  
- **仅某课题**：加 `slot/*` 或 `proj/*`，仍只在一个 Collection。  
- 左侧用 Zotero **保存的搜索** 代替旧 Collection 树（如 `tag:scope/core`、`tag:slot/1a-2a`）。

### 3.3 从旧 Collection 迁移（一次性）

1. 存量文献 bulk-tag `dom/*`、`slot/*`、`scope/*`。  
2. 合并旧 Collection → 自有论文进 `My Papers`，基石进 `Cornerstone`，其余进 `Everything`。  
3. 双机确认 Attanger 与「链接附件根目录」指向新 `literature/` 结构（[[3.1]] §1.3）。

## 4. Obsidian S1：平面 Literature Notes

- **路径**：`7 可复用知识库/literature/{citekey}.md`（文件名 = BBT citekey）。  
- **可选前缀**：`LR_` 仅用于文件管理器排序，**不**建子文件夹。  
- **何时建 S1**：`scope/core`、已进主稿引用、或列入某 `MOC-*`；其余可只在 Zotero 保留条目。  
- **正文结构**（模板见 [[7 可复用知识库/literature/_templates/literature-note]]）：
  1. One-liner  
  2. 框架 / 方法要点  
  3. 与我工作的接口（slot、分割策略等）  
  4. 引用场景（哪篇主稿、哪类 talk）  
- **frontmatter** 须含 `zotero_tags`，与 Zotero tag 镜像，便于 Dataview / AI。

**项目侧**

- 在 `00_ResearchTrack` 或 `文献-阅读队列.md` 中列 citekey 链接即可。  
- **勿**在 `1 主线项目/前期产出/<项目>/literature/` 再养一套（与 [[3.5 Workflow ：Legacy 前期项目入库]] 中「项目印象笔记归档」不同：后者是**项目私有实验笔记**，不是 S1 文献库）。

## 5. S2：主题 MOC（虚拟分类）

- 目录：`7 可复用知识库/literature/_views/`  
- 文件示例：`MOC-全局基石.md`、`MOC-海马组织维度.md`、`MOC-疗效预测.md`  
- 内容为 **链接列表 + 一两句说明**，不粘贴 PDF 摘要全文。  
- 新建 MOC 时同步维护，避免在多个项目里各写一份「重要文献清单」。

## 6. 工具分工

| 场景 | 首选 | 材料 |
|------|------|------|
| 改稿、talk 提纲、标书段落 | Cursor + Copilot | S1 笔记、项目 digest、`[@citekey]` |
| 单篇精读、核对图表 | Zotero LLM | PDF（S0） |
| 跨 10+ 篇原文对照、专题综述式问答 | Gemini AI Studio / NotebookLM | `_ai_sessions/` 临时 PDF 包 |
| 批量检索入库 | PubMed → CSV → Zotero | [[0 工作流/工具箱/归档/Work_PubMed摘要导出与CSV文献提取工作流]] |

## 7. 专题外置 AI（`_ai_sessions`）

详见 [[0 工作流/工具箱/ai专题/README]]。

**要点**

- 仅在专题深读时，将选定 PDF **复制**到 `0 工作流/工具箱/ai专题/<topic>-<YYYYMMDD>/`。  
- 用毕 **整夹删除** 或移出 vault 冷备份；**禁止**回写为第二套 Zotero Collection。  
- 若某专题 **连续数周** 使用 NotebookLM，可在 Google Drive 另建 `NotebookLM-drop/<topic>/`（按需同步），仍不是坚果云 canonical 库的一部分。  
- 生成方式：Zotero 按 tag 筛选 → 手动复制；或日后脚本（非必须）。

## 8. 硬规则（检查清单）

- [ ] 每篇文献在 Zotero 中 **只属于一个** Collection（Cornerstone / My Papers / Everything）。  
- [ ] 科学 / 项目归属只改 **tag**，不新建 Collection 树。  
- [ ] PDF 不在 `1 主线项目/` 下长期存放。  
- [ ] S1 笔记只在 `7 可复用知识库/literature/` 平面目录。  
- [ ] 外置 AI 只用 `_ai_sessions/`（或 Drive 的 `NotebookLM-drop/`）临时副本。  
- [ ] 印象笔记迁移完成后删除 `印象笔记存档/`，不维护双轨文献池。
