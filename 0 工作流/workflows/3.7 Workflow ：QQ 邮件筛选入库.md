## 四、「要不要处理」筛选 rubric

### 强信号（默认 action_required）

- 主题/正文：`截止` `请于` `due` `deadline` `revision` `invite` `基金` `申报` `征稿` `审稿` `Editorial Manager` `返修` `R1` `R2`
- 发件人域：`editorialmanager.com`、期刊域名、院内 `*@163.com`、学校/学会域名

### 弱信号（标「待你确认」）

- 仅「请关注」「最新一期」无具体日期  
- 长抄送、群发通知体

### 默认 skip

- 营销、订阅、验证码、快递、无关会议邀请 → 卡片标 `skip`，确认后**删除** drop 且不建 active
- `精影讲堂` 的预告 / 总结 / 常规会务提醒默认视为 `skip`；除非邮件里出现需要你明确动作的任务，或你点名要整理

## 七、Phase 2 · QQ IMAP 自动拉取

> 手动流程满意后再启用；凭证**不进 vault**。

1. QQ 邮箱 → 设置 → 账户 → 开启 **IMAP** → 生成**独立密码**  
2. 环境变量（用户级，非仓库）：
   - `QQ_MAIL_USER`（完整地址）
   - `QQ_MAIL_IMAP_PASSWORD`（独立密码）
3. 拉取：

```powershell
cd "c:\Users\41516\Nutstore\1\MyObisidian\0 工作流\scripts"
powershell -NoProfile -ExecutionPolicy Bypass -File .\Setup-QQMailCredentials.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\Invoke-QQEmailFetch.ps1 -UnreadOnly -MaxCount 20
powershell -NoProfile -ExecutionPolicy Bypass -File .\Merge-EmailDrop.ps1
```

4. 输出写入 `_email_drop/`（与手动同 frontmatter）  
5. 开 Cursor 时 Hook 可调用 `Merge-EmailDrop.ps1` 刷新 [[0 工作流/邮件待整理队列]]（**不**自动解析邮件）  
6. 可选：Windows 计划任务每 2～4 小时跑 `Fetch-QQEmail.ps1`

| 参数 | 默认 | 说明 |
|------|------|------|
| `-UnreadOnly` | 开 | 仅未读 |
| `-MaxCount` | 20 | 单次上限 |
| `-SinceDays` | 7 | 时间窗 |
