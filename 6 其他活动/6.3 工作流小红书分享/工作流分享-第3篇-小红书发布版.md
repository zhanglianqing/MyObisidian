# 第 3 篇

## 标题

审稿邮件别再堆三周：邮件怎么进 vault

## 正文贴文版

前面讲过我做了一套每周自动化整理/规划，并为此搭了框架。规划工作的来源，除了每周临床排班，大致有两类：

1. **直接指派的任务** — 我会跟 Cursor 对话处理。但直接对话有个坑：它容易以为你要马上开干，然后吭哧吭哧往下做。所以我专门做了「小助理」：输入 `小助理：xxxx` 时，它只捕获、按项目记进去，并保证能汇总到每周工作台，不会擅自展开执行。（GitHub 上小助理单独一块，见文末链接。）
2. **邮件来的任务** — 今天主要讲这个。最常见的是审稿邀请，最容易在 QQ 邮箱里躺很久；再打开时常忘了 deadline 在哪一行、Editorial Manager 链接在哪、上次读到哪。所以我把「邮件进来」和「审稿续上」放一篇讲。

---

**邮件：两层，别混。**

先说自动拉取：目标是**不开邮箱、不复制粘贴**，让 Cursor 把未读邮件写进 vault 暂存区 `_email_drop/`。

你可以直接对 Cursor/Codex 说：

```text
我想让 QQ 邮箱未读邮件自动拉进 Obsidian 的 _email_drop/，再用手动「邮件整理」出摘要卡片。
请按 starter 里 notes/03-email-peer-review/ 的邮件 workflow 帮我落地：
IMAP 拉取脚本、Merge 队列、email-inbox 规则。
先列出我要在本机配置什么（授权码放哪），不要写进 vault；我确认后再改文件。
```

它会帮你把流程搭起来，并告诉你要准备什么。我用的 QQ IMAP：进邮箱 **设置 → 账号与安全 → 安全设置**，开启 POP3/IMAP，点 **生成授权码**（16 位，不是 QQ 登录密码）。授权码按 Cursor 提示放在本机 `%USERPROFILE%\.qq_mail_imap.env`，不进 vault、不进 Git。Obsidian 可以坚果云同步笔记，邮箱凭证我刻意每台电脑各配一份。

![[_assets/ep03-qq-imap-1-account-security.png]]
*设置侧栏找「账号与安全」，别在普通邮件设置里翻半天。*

![[_assets/ep03-qq-imap-2-generate-auth-code.png]]

配置好后，脚本会把未读邮件写成 drop 文件。**整理**是另一步：对 Cursor 说「邮件整理」，它读 `_email_drop`，每封输出一张摘要卡片，**我确认后**才写入 `10/` `11/` `12/`。我习惯以周为单位安排，所以把拉取 + 整理接进了小助理：每周说「小助理整理下周工作」，它会先拉邮件、再出卡片。你也可以改成每日整理，口令一样，习惯自定。

**确认后：每篇稿一个文件夹，笔记长什么样**

卡片确认（或 EM 上点完 Agree 后跟 Cursor 说一声）→ 在 `10 杂志审稿/active/` 建子文件夹，**文件夹名以稿号开头**，后面加几个字的短题目。里面一篇笔记 + 下载的 PDF 放同目录。

单篇笔记我固定这几块（和 ResearchTrack 一样，是让 AI 帮我搭出来的）：

| 小节 | 干什么 |
|------|--------|
| **日程** | 邀稿、接受、计划动笔、编辑部截止 — 表格一眼看完 |
| **进度** | 勾选清单：捕获邮件 → 下 PDF → 写意见 → 提交 EM |
| **Editorial Manager** | 查看稿件 / 提交审稿 / 登录链接和用户名，**从邮件抄进来，不用回邮箱找** |
| **摘要要点** | 邀稿邮件里的 abstract 压缩成几条，locate 时 AI 先读这个 |
| **Review comments (working)** | 边读 PDF 边记；你说「写进 comment」AI 才补英文 |
| **邮件来源** | 链回 `_email_drop` 原文，方便核对 |

**隔几天再 locate，信息还在**

审稿常要等临床空档。任务一暂缓，邮箱里那封 invitation 就沉下去了。vault 落地后：稿号、EM 链接、deadline、working comments 写到哪，都在上面这一页。等你要开工了，对 Cursor/codex 说：

```text
我打算继续 NIMG 审稿，先帮我 locate，阅读 readme
```

它会去 `10 杂志审稿/active/` 找到笔记，读 `10 杂志审稿/README` 里的协作约定，回报进度，分屏打开笔记和 PDF，接着写 comment。和第 2 篇同一套逻辑：上下文留在项目里，工作台只抽一个下一节点。

**审稿：AI 辅助的思路和边界**
刚好也跟大家分享一下AI辅助审稿的思路。
AI 在这套 workflow 里**不替我写审稿意见**，不帮我做critical thinking。主要做三件事：1. 把口语化的疑点补成可定位、可提交的英文 comment。如果你有很多时间，那么自己把你的comment写完整当然是好的。但我比较懒，英文水平也一般。因此我会对ai用口语化的语言直接批一些要点，然后ai帮我补充完整；
2.阅读省点劲儿。有时候是manu写作本身有问题，有时候是我自己偷点懒。我会让ai先帮我总结一下这个段落他主要的内容，再来逐句阅读，方便我迅速评估结构性的问题。有时候其实作者想表达的意思maybe是对的，但语言有些问题阻碍阅读，而ai在这方面的理解力往往比我好，我更能迅速给出更合理的建议
3. 不可避免地和ai进行讨论，问它怎么看，提供一些审稿思路。不过最终的最终，它提供的思路是我个人认可的，才会落实下来

而上述的边界写在 `10 杂志审稿/README`，这样不用每次都找出来输入。主要内容包括：每条 comment 须能定位到章节和原句；不把随口吐槽自动升级成 major concern；不把一个语法问题扩成方法学批评；没说「合并」「删减」就不擅自改已有 comment；若 comment 可能忽略了文中已写内容，先提示、等我确认再记。

## 正文短版

承接前几篇：这篇讲 **邮件怎么进 vault，审稿怎么隔几天接着做**。

**两类任务来源。** 直接指派走 Cursor 对话，但容易误触发立即执行；临时记录用 `小助理：xxxx`。邮件任务（审稿、基金、征稿）走 `_email_drop` +「邮件整理」。

**自动拉取。** 对 Cursor 说「按 starter 03-email-peer-review 帮我把 QQ 未读邮件拉进 _email_drop」；QQ 后台开 IMAP、生成 16 位授权码，放本机 `.qq_mail_imap.env`。整理时说「邮件整理」或「小助理整理下周工作」，AI 出摘要卡片，确认后写入 `10/11/12`。

**卡片 → 文件夹。** 确认后 `active/稿号 短题目/`，笔记含日程、进度、EM 链接、摘要要点、working comments；提交后整夹移 `archive/`。

**续审。** `继续 xx 审稿，locate，读 readme` → 找 active 笔记、报进度、接着写 working comments。

**AI 边界。** 只补可定位 comment；major concern 人定；README 写清禁区。

starter 分两块：`notes/03-email-peer-review`（邮件+审稿）、`notes/03-assistant-capture`（小助理）。
