# 工作流分享 · 写作与脱敏规范

## 交付格式（默认仅此三项）

```markdown
## 标题

## 正文贴文版

## 正文短版
```

不默认写：分镜、carousel、PPT、PNG、即梦提示词、口播/视频脚本。分页由小红书或后续人工处理。

---

## 语气

- 像跟朋友吐槽完，顺便分享一个省事办法。
- 工具名（Obsidian、Cursor）可留；「AI 原生、闭环、赋能」能省则省。
- 别说「折腾半年」；实际约 **1 个月零碎时间**。
- 读者怕技术：**说法要轻，干货不省**。

---

## 脱敏

| 别写 | 改成 |
|------|------|
| 单位、科室、期刊名 | 泛化 |
| 课题名、娃名 | 课题 A、娃 |
| 路径、主机名 | 你的笔记文件夹 |
| 邮件/基金细节 | 审稿邀请、基金通知 |

### 杂志审稿（正文 + 截图）

**稿号、稿件标题、作者姓名、摘要/正文片段、EM 用户名等，一律脱敏。** 成稿、素材页、配图里都要检查，不能只在正文里泛化、截图里留真值。

| 类型 | 别写 | 改成 / 处理 |
|------|------|-------------|
| 稿号 | `IMAG-26-0219` | `JOURNAL-26-xxxx` 或打码 |
| 稿件标题 | 完整英文/中文题名 | 泛化短题，或马赛克 |
| 作者 | 真实姓名列表 | `Author A et al.` 或打码 |
| 摘要/正文 | 可识别段落 | 删改概括，或打码 |
| EM 用户名 | 真实 login | `L***-344` 或 `Reviewer-xxx` |
| 期刊名 | 可识别刊名 | 泛化（如 *Imaging Neuroscience* → 某 imaging 期刊） |

**截图**：发布前逐张看——稿号、标题、作者、邮件正文、笔记 frontmatter、ReviewTrack 行都要马赛克或换脱敏 demo。**第 3 篇发布教训**：成稿截图里稿号未脱敏，发布时已手动打码；以后成稿阶段就用脱敏 demo 或 `_assets` 打码版，不要临发布才发现。

GitHub starter 示例已用 `JOURNAL-26-xxxx`；vault 内真稿截图**不要**直接进小红书/Git。

## 写稿口令

```text
按写作与脱敏规范写第 X 篇：
只产出标题、正文贴文版、正文短版；脱敏；场景开头。
```

---

## 发布前自检

- [ ] 场景开头，不是科普定义
- [ ] 读一遍像平时说话
- [ ] 已脱敏（含审稿：稿号、标题、作者、截图）
- [ ] 配图逐张检查 frontmatter / Track / 邮件正文无真值
- [ ] 只有标题 + 贴文版 + 短版，无多余附件
