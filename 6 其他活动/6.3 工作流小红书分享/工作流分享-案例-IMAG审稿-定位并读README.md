# 案例 · 继续审稿：定位 + 读约定 + 稿件笔记

## 场景

隔几天再打开 Cursor 继续审稿，不想自己翻文件夹找稿、也不记得上次读到哪、comment 该怎么记。

## 用户口令

`我打算继续IMAG审稿，先帮我locate，阅读readme`

## 工作流要点

- **定位**：AI 在 `10 杂志审稿/active/` 找到对应稿件文件夹（MD 笔记 + 本地 PDF）。
- **读约定**：先读 [[10 杂志审稿/README]] 里的「给 Codex：审稿协作习惯」，后续 comment 按 vault 约定写入 `Review comments (working)`。
- **恢复上下文**：从稿件笔记 frontmatter 和进度区读出状态（已接受、round 1、截止日、已写到 Discussion 哪一段），不用用户重复说明。
- **分屏续审**：Cursor 左侧对话、右侧直接打开稿件笔记——frontmatter、日程、进度勾选、EM 链接、摘要要点、working comments 一页可见，接着读 PDF 写 comment 即可。

## 对话里 AI 回报的关键信息（摘要）

| 项 | 内容 |
|----|------|
| 入口 | `10 杂志审稿/active/IMAG-26-0219 …/` |
| 协作约定 | 用户边读边说的疑点 → 补成可定位、可提交的 comment → 写入 working 区 |
| 状态 | 已接受，第 1 轮 |
| 截止 | 2026-06-13（建议 2026-06-12 前提交） |
| 进度 | 已有 working comments；读到 Discussion 小脑/基底节段附近 |

## 可分享的讲法（草稿）

- **痛点**：审稿邀请接完就忘；再打开不知道文件在哪、comment 记什么格式、上次读到哪。
- **做法**：每篇稿在 Obsidian 里一个文件夹 + 一篇笔记；`10 杂志审稿/README` 写清 AI 怎么配合；继续审时说「locate + 读 readme」即可续上。
- **亮点**：不是从零问「这篇稿讲什么」，而是 **locate → 读约定 → 报进度 → 分屏打开笔记**，直接接着写 comment。
