# 示例项目 · ResearchTrack

> 这是一个脱敏示例，用来展示 `ResearchTrack` 应该承担什么角色。  
> 它不是完整项目文档，也不保存原始数据；项目真实资料仍放在项目文件夹内。

## 这个文件负责什么

`ResearchTrack` 是项目自己的运行轨迹页，主要回答四个问题：

1. 这个项目现在处在什么阶段？
2. 最近一次关键判断是什么？
3. 下一步要推进什么？
4. 相关材料、记录、结果入口在哪里？

它不是每天打开的工作台，也不是完整 todo list。  
日常视图可以从 `同期项目-下一节点` / `本周工作台` 汇总；需要回到项目上下文时，再点回本页。

## 当前焦点

| 项 | 状态 |
|----|------|
| 项目阶段 | 初稿修改后，准备进入下一轮数据核对与叙事收束 |
| 当前判断 | 主结果可以保留，但需要补充方法解释和敏感性分析摘要 |
| 下一步 | 处理合作者反馈中的“方法与结果解释”部分，并更新改稿台账 |
| 本周衔接 | 若进入本周执行，可在 `本周科研推进` 中拆成 2-3 条可勾选任务 |
| 工作台衔接 | `同期项目-下一节点` 中只保留一条当前节点，例如“完成方法解释修改” |

## 项目资料入口

| 类型 | 入口 | 备注 |
|------|------|------|
| 项目总览 | `项目总览.md` | 研究问题、样本、主要结果的一页摘要 |
| 改稿记录 | `改稿记录/` | 每轮修改单独成页 |
| 会议记录 | `会议记录/` | 只保留和项目决策有关的会议 |
| 文献线索 | `文献/` 或 Zotero citekey | 不在本页堆全文笔记 |
| 数据说明 | `数据说明.md` | 写清数据位置、变量含义、不能公开的内容 |
| 投稿材料 | `投稿材料/` | 主稿、补充材料、cover letter 等 |

## 待办池

> 这里只放与项目上下文强相关的待办。  
> 每周真正要执行的细则，建议迁到 `本周科研推进`。

- [ ] 核对主要结果表述是否与当前统计结果一致
- [ ] 补充方法部分对关键参数的解释
- [ ] 整理一段“局限性与下一步研究”文字
- [ ] 更新项目总览页的一句话结论

## 和工作台的关系

推荐流向：

```text
项目资料和完整上下文
  ↓
本 ResearchTrack
  ↓
抽出 1 条当前下一节点
  ↓
同期项目-下一节点
  ↓
本周科研推进 / 本周工作台
```

示例下一节点：

```markdown
- [ ] 示例项目：完成方法解释修改并更新改稿台账 → [[示例项目/00_ResearchTrack]] ⏳ 2026-06-10
```

## 给 Cursor / Codex 的使用口令

```text
请参考 examples/00_ResearchTrack.example.md，
为当前项目建立一个脱敏同结构的 ResearchTrack。
要求：
1. 保留项目上下文、当前焦点、资料入口、待办池、决策记录。
2. 不把所有本周任务都堆在 ResearchTrack；本周执行细则另放到本周科研推进。
3. 为这个项目抽出一条“当前下一节点”，建议写入同期项目-下一节点。
4. 写入工作台或下一节点前，先列建议并等我确认。
```
